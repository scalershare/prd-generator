# 视觉设计确认流程（v4.2 新增）

"功能都对，但看起来不高级"是 AI 辅助开发最常见的失望来源。原因通常不是 AI 审美差，而是：**没有参考对象、风格方向没对齐、没有出多版让用户挑、管理后台直接用了组件库默认样式**。

> 案例（某高职职业测评系统）：设计方向定为"精密仪器感、克制"，执行得很一致，但用户心里想要的是"高大上、精美"。两者都没错，只是从没对齐过；而管理后台大量使用 Element Plus 默认表格表单，一眼就是"后台模板"。上线后用户要求整体返修。

---

## 一、需求探查阶段必须问（每轮 2–3 个）

1. **参考网站**：给 3–5 个你觉得好看的网站/App（不限行业），分别喜欢它哪一点？（配色/排版/动效/质感/插画）
2. **不喜欢的**：有没有你明确不喜欢的风格？
3. **三个形容词**：希望用户第一眼的感受（如"专业、可信、年轻"/"高级、精致、有科技感"）
4. **使用场景与设备**：主要在手机还是电脑？网络条件如何（校园网/4G）？用户设备档次？
5. **品牌资产**：有没有 Logo、主色、指定字体、需要出现的机构标识？
6. **"惊艳"的预算**：大图、视频背景、3D、复杂动效会拖慢中低端手机和弱网——用户愿意为此付出多少加载时间？

用户说"你看着办"时，也要给出 2–3 个方向让他选，而不是直接定一个。

## 二、出方案再开发（不要直接写页面）

1. 根据参考生成 **2–3 套风格方向**，每套包含：配色、字体、一个核心页面（如首页）的电脑版和手机版效果图
2. 用户挑选或组合 → 写成**设计规范文件**（DESIGN.md：颜色 token、字体、间距、圆角、阴影、动效时长、组件规则）
3. CLAUDE.md 中要求：任何 UI 工作先读 DESIGN.md；偏离规范要先问用户
4. 先做 1–2 个代表性页面给用户确认，再铺开到全部页面

## 三、PRD 中要写的内容

- 设计规范文件的位置和核心 token
- **管理后台也要设计**：数据看板式首页、表格/表单的统一定制样式（不要只用组件库默认主题）、空状态和加载态的插画/文案
- 每个页面的电脑版和手机版布局差异（不是"自适应"一句话）
- 字体策略：中文字体文件很大（一个字重常见几 MB），需要子集化、自托管、缓存策略，并给出首屏体积预算
- 动效清单：只在少数关键时刻使用（如结果揭晓），其余页面保持克制

## 四、验收

- 每批页面完成后，提供电脑 + 手机截图给用户确认（不是只说"已完成"）
- 自动检查：控制台报错、手机横向溢出、首屏加载体积
- 真机检查：至少一台中低端安卓 + 一台 iPhone，在 4G 下打开
