# 运营场景与数据生命周期清单（v4.2 新增）

PRD 最容易漏掉的不是"核心功能"，而是**管理员和老师每天都会遇到的琐事**。这些琐事在需求探查时用户想不起来，上线第一周就会集中爆发。

> 案例（某高职职业测评系统试点）：PRD 只写了"Excel 批量导入学生"。上线后一周内陆续发现缺：单个添加学生、编辑学生信息（补手机号、转班）、一键解锁被锁账号、按姓名搜索、按进度筛选、教师离职后重新启用、管理员重置密码后告知新密码的方式、导入时班级名写法不统一（"建工2401"和"建工 2401"）。全部是 P0——没有它们，老师就得找技术人员手动改数据库。

---

## 一、每类核心数据的完整生命周期（逐项过）

对 PRD 中**每一类由人管理的数据**（用户、班级、商品、订单、内容……），逐项确认下表。任何一格答不上来就是漏洞。

| 操作 | 要确认的问题 |
|---|---|
| 新建（单个） | 只有批量导入够不够？来了一个插班生/新员工怎么办？ |
| 新建（批量导入） | 模板谁提供？表头写法不一致能否识别？重复数据跳过还是覆盖？部分失败怎么展示？上限多少行？ |
| 查看 / 搜索 | 按什么搜（姓名、编号、手机号）？搜索是全量还是只搜当前页（常见 bug）？ |
| 筛选 | 按状态/进度/分组筛选？老师最常问的问题是什么（"谁还没做完"）？ |
| 编辑 | 哪些字段能改、谁能改？改了关联数据怎么办（转班后历史记录归属）？ |
| 停用 / 启用 | 停用后能否再启用？停用的人还能登录吗？已产生的数据保留吗？ |
| 删除 | 真删还是软删？有关联数据时能否删？误删怎么恢复？ |
| 重置（密码等） | 重置成什么？怎么告诉当事人？下次登录是否强制修改？ |
| 解锁 | 输错锁定后谁能解锁？要等多久自动解锁？ |
| 导出 | 谁能导出、导出什么字段、时间用哪个时区？ |
| 转移 / 归属变更 | 换班、换负责人、离职交接 |

**写进 PRD 的方式**：每类数据一张"生命周期表"，列出每个操作的角色、入口页面、API、边界规则。

## 二、角色的"一天"走查

需求探查时，让用户按时间顺序描述每个管理角色**真实的一天/一个学期**，而不只是描述功能：

- 开学/上线第一天：账号怎么发下去？初始密码怎么告诉几百人？首次登录改密，有人忘了怎么办？
- 日常：有人反映"登不上"——老师能自己处理吗？还是要找技术？
- 集中使用时段：老师在教室/机房组织几十上百人同时用，老师需要看到什么（实时进度？谁卡住了？）
- 期末/结束：数据导出给谁、用来干什么？账号要不要统一停用？
- 人员变动：老师离职、学生退学、换班

**原则**：凡是"只能找技术人员改数据库"才能解决的日常问题，都应该有界面入口。

## 三、账号发放与身份核验（面向学生/员工的系统必问）

- 初始密码规则：可预测（前缀+学号）便于发放，但需要首次登录强制修改 + 账号锁定防喷洒
- 首次登录核验：手机号后四位等二次核验——**没有手机号的账号**怎么办？（手机号常常是选填）
- 忘记密码：自助找回（需要短信/邮箱）还是找老师重置？V1 通常选后者，但必须有入口
- 密码复杂度：要求越高，学生越容易忘、老师重置工作量越大——跟用户明确权衡

## 四、数据导入的"脏数据"预案

真实 Excel 一定是脏的，PRD 必须定义处理规则：

- 全角/半角、首尾空格、中间空格（"建工 2401"）→ 统一归一化（NFKC + 去空白）
- 数字被 Excel 存成 `2024010101.0`、手机号变成科学计数法
- 表头写法不同（"学号"/"学生学号"/"账号"）、列顺序不同
- 引用不存在的分组（班级/专业）→ 自动新建还是报错？
- 第二次选择文件时上传控件无反应（`limit=1` 类前端 bug）——验收时要专门测"换文件"
